1. Project overview

ACE Basketball League is a private Sunday league that plays in Glendale. Members and visitors read season results, player totals, head-to-head matchups, rules, and photos. Captains and the maintainer use a password-protected admin area to run the preseason draft and maintain players, seasons, and rosters.

Dae Young actively started the project in April 2025. He designed the data structure himself. An LLM helped write the original Google Apps Script that syncs a guidebook spreadsheet into Supabase. He has been entering game and tournament data through that sheet. Moving that entry onto the website is the next step and is not built yet.

In September–October 2026 the work expanded into a Flask web application. The public site publishes the Supabase tables. Admin pages manage players, seasons, the draft, and the roster. Captains have already run a real draft on the deployed Render service.

3. Technical architecture and design

Frontend
  Server-rendered Jinja templates and one CSS file. Small browser scripts sort tables and run the moments gallery and draft room. There is no separate frontend framework.

Backend
  One Flask application, app.py (about 2,800 lines), with Flask-SocketIO. Supabase is called with urllib against the REST API. There is no local database and no automated test suite in the repository.

Database
  Supabase Postgres. The site reads seasons, player_stats_total, player_stats_by_season, team_matchup_strength, players, team_members, and team_moments. Photos go to a public Supabase Storage bucket. Derived totals are rebuilt by SQL functions that live in Supabase, not in git.

Authentication
  Two shared passwords, ADMIN_PASSWORD and CAPTAIN_PASSWORD, checked with an HMAC compare and stored in a Flask session cookie (7 days). Failed logins are limited to 5 per IP in 10 minutes, in process memory. Captains are redirected away from every admin path except the draft room. Socket events require that same session.

Database authorization
  SQL files in supabase/ open row-level writes to the API role (using true). The password gate is in Flask. Anyone who has the API key can write those tables without the admin password. See supabase/seasons_admin_policies.sql and supabase/team_members_admin_policies.sql.

Deployment
  Render web service on the Starter compute plan: 0.5 CPU, 512 MB RAM. Paid Render instances stay running and do not spin down the way the free plan does. Python 3.12.8, bound to PORT. Custom domain acebasketballteam.com, registered at Namecheap through 21 September 2027. The app redirects www to the apex host.
  On 13 October 2026 at 12:14 PT the homepage returned HTTP 200. The origin header was Werkzeug/3.1.9 Python/3.12.8, with Cloudflare in front, which is consistent with Render.
  Plan specs are from Render's compute-plan documentation (legacy name "starter" = plan id 0.5c-512mb). A deploy or restart still clears the in-memory draft.

How data moves
  1. Game and tournament rows are entered in the guidebook sheet. The sheet syncs them into Supabase and runs refresh_all_stats. That script is not in this repository.
  2. Member Stats calls refresh_player_totals, then reads player_stats_total. A failed refresh still shows the last stored totals.
  3. Draft and seed state live in one in-memory object and are broadcast with Socket.IO. A restart clears that room. History is capped at 100 seed runs.
  4. After a draft, an admin picks the season and the seed-to-team mapping and explicitly saves. That inserts team_members. The Roster page can then move, add, remove, or clear players for that season.

What remains in use
  Supabase is still the database.
  The guidebook sheet is still the game and tournament entry path.
  Apps Script is still part of that sheet workflow. It is absent from this repo, which does not mean it was retired.
  The public website replaced the spreadsheet as the place people read stats.
  The Games and Tournament admin pages are placeholders. Their own notes say the future job is to insert game_results, player_played_games, and tournament_matches.

Documented technical decisions
  Render would not boot with eventlet. The service was switched to Socket.IO's threading mode so it could bind to PORT. Commit 8c4548f, 21 September 2026.
  Seed odds are calculated, not simulated. Losing teams get a higher chance at the first seed, blended 80 percent toward loss share and 20 percent toward equal odds. A recursive walk then computes the exact chance of each seed. See PROBABILITY_BLEND and build_seed_probability_matrix in app.py.
  Names are not identities. players.id is a UUID. Duplicate display names are allowed. The draft label uses the comment field when two active players share a name. Legacy stat tables were given a nullable player_id and backfilled by exact name match. Unmatched "(NM)" names were seeded as non-members. Non-members are excluded from the draft pool. See supabase/players.sql and supabase/player_stats_add_player_id.sql.
  Roster save is manual so a bad draft does not write itself into the season. The admin chooses the season and the seed-to-team mapping.
  Totals should rebuild when data is saved, not on every page view. The page-load refresh both did extra work on a read and skipped a season. The full rebuild, refresh_all_stats, belongs at the end of the sheet import. The Member Stats page still calls the narrower function.
  The domain outage on 12 October 2026 was not an app failure. Namecheap had replaced the nameservers after an unverified WHOIS contact. The homepage was back on 13 October 2026.

Designed the data model and season workflow for ACE Basketball League, a private Sunday league, starting in April 2025. Interview examples

Derived totals
  The member-stats page rebuilt totals on every visit, and the function it called skipped the newest season. The full rebuild already lived at the end of the sheet import. This is a story about derived data, about the write owning the refresh, and about a read-path fallback hiding a bug.

Player identity
  Display names collided, including two active people with the same name. Identity moved to a UUID, the draft UI showed the comment, and old stat rows were linked by name with a leftover report for mismatches.

Render boot
  The service failed to boot under eventlet. Switching Socket.IO to threading mode fixed the boot. The follow-on constraint is that draft state sits in that one process. Starter stays up while the service is running, and a deploy or restart still clears an in-progress draft. A real draft has already been run on that service.

Database access
  Database policies allow the API key to write. The admin password is only enforced in Flask. Describe it as a short-term choice for a single shared key, and as something to tighten before treating the admin API as a public integration.
